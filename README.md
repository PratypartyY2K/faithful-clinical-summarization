# Faithful Clinical Summarization via Atomic Claim Verification

This repository implements a MIMIC-III clinical summarization pipeline designed to study the original research question:

Compared to traditional end-to-end evaluation metrics, does hallucination detection considerably improve when a generated clinical summary is broken down into atomic claims and each one is independently verified against the source transcript?

The practical workflow now is:

1. ingest discharge summaries from `NOTEEVENTS.csv`
2. prepare summarization splits and weakly supervised verifier splits
3. train a summarizer
4. train a claim verifier
5. evaluate generated summaries with both overlap metrics and claim-level support metrics

## Project Framing

Current research question:
- Compared with traditional end-to-end metrics such as ROUGE and BERTScore, does hallucination detection improve when generated summaries are decomposed into atomic claims and each claim is independently verified against the source note?

Working hypothesis:
- Summary-level overlap metrics will miss clinically important factual errors that become visible when summaries are decomposed into atomic claims and scored claim-by-claim for entailment, contradiction, or lack of support.

Current proposed method:
- train a clinical summarizer on MIMIC-III discharge-note sections
- generate weakly supervised verifier data by extracting atomic claims from reference summaries
- train an NLI-style verifier on entailment / contradiction / neutral examples
- evaluate generated summaries with ROUGE, BERTScore, claim support rate, contradiction rate, and overlap-vs-faithfulness disagreement analysis

This framing matches the original proposal and is now directly supported by the preprocessing and evaluation code in the repository.

## Current Status

What works now:
- MIMIC-III discharge-summary ingestion into `data/mimiciii/raw/*.jsonl`
- processed summarization splits under `data/mimiciii/processed/summarization/*.jsonl`
- processed weakly supervised verifier splits under `data/mimiciii/processed/verifier/*.jsonl`
- PEFT / QLoRA causal summarizer training
- DeBERTa-style verifier training on dialogue-claim pairs
- summarizer-only evaluation with ROUGE and BERTScore
- full pipeline evaluation with claim support, contradiction, and disagreement analysis
- debug preprocessing with shortened targets

Important limitation:
- verifier supervision is weakly supervised rather than manually labeled
- entailment claims come from reference-summary claim extraction
- contradiction claims are generated by deterministic clinical-style perturbations
- neutral claims are sampled from claims attached to other encounters

This means the verifier path is operational for the original research question, but the scientific claims should be framed as weak-supervision results unless you later replace these labels with manual or LLM-validated annotations.

## Current Best Results

Best full-data baseline:
- `ROUGE-1`: `0.2541`
- `ROUGE-2`: `0.0980`
- `ROUGE-L`: `0.1843`
- `ROUGE-Lsum`: `0.1850`
- `BERTScore F1`: `0.8409`

Best current model after target filtering:
- `ROUGE-1`: `0.2759`
- `ROUGE-2`: `0.1078`
- `ROUGE-L`: `0.1975`
- `ROUGE-Lsum`: `0.1970`
- `BERTScore F1`: `0.8432`

Interpretation:
- the `narrative-only` experiment improved every reported metric
- target-style consistency mattered more than the decoding sweeps tested so far
- the main remaining problems are admission-copying, generic boilerplate, and unsupported details on complex cases

## Expected Data Layout

Raw data is expected under `data/mimiciii/`.

```text
data/mimiciii/
  NOTEEVENTS.csv
  raw/
    train.jsonl
    validation.jsonl
    test.jsonl
  processed/
    summarization/
      train.jsonl
      validation.jsonl
      test.jsonl
    verifier/
      train.jsonl
      validation.jsonl
      test.jsonl
```

Each raw example contains:
- `example_id`
- `dialogue`
- `summary`
- `claims`

For the default MIMIC ingestion path, raw `claims` remain `[]`. Verifier supervision is generated during `scripts/prepare_datasets.py` from the reference summaries.

Processed summarization rows contain:
- `example_id`
- `input_text`
- `target_text`
- optional `target_text_full`
- optional preprocessing metadata such as `target_sentence_limit` and `narrative_only`

## Core Scripts

`scripts/ingest_mimiciii_notes.py`
Reads `NOTEEVENTS.csv`, extracts source sections and target `brief hospital course` text, and writes raw JSONL splits.

`scripts/prepare_datasets.py`
Builds summarization and verifier splits from raw examples. It also supports:
- `--target-sentence-limit` for shortened-target debug datasets
- `--verifier-claim-extractor-backend` for heuristic or LLM claim decomposition
- `--verifier-max-claims-per-example` to control verifier dataset size
- `--verifier-seed` for deterministic neutral-claim sampling

`scripts/train_summarizer.py`
Trains either a seq2seq baseline or a causal summarizer. The recommended path is a causal Gemma QLoRA run with checkpoint saving and auto-resume enabled.

`scripts/evaluate_summarizer.py`
Runs summarizer-only generation and overlap evaluation. It accepts:
- raw examples with `dialogue` / `summary`
- processed summarization rows with `input_text` / `target_text`

It also supports decoding controls such as:
- `--num-beams`
- `--no-repeat-ngram-size`
- `--repetition-penalty`
- `--length-penalty`

`scripts/train_verifier.py`
Trains an NLI-style verifier over dialogue-claim pairs with labels `contradiction`, `neutral`, and `entailment`.

`scripts/run_pipeline.py`
Runs one generate-and-verify example and returns the generated summary, extracted claims, and verifier scores.

`scripts/evaluate_pipeline.py`
Evaluates the full test pipeline and writes aggregate overlap metrics, claim-level faithfulness metrics, verifier test metrics, qualitative unsupported-claim examples, and overlap-vs-faithfulness disagreement analysis.

`scripts/export_claim_annotations.py`
Builds a CSV annotation sheet from generated summaries and extracted claims so a human reviewer can label each claim as supported, contradiction, or neutral/unsupported.

`scripts/evaluate_human_annotations.py`
Scores completed human annotation sheets against verifier predictions and overlap metrics.

## Recommended Experiments

For the paper, the most relevant experiment set is:

1. Summarizer baseline
- Gemma 3 12B QLoRA trained on the default processed summarization dataset

2. Verifier model
- DeBERTa-v3-large or a smaller verifier trained on the processed verifier dataset

3. Main evaluation
- compare ROUGE and BERTScore against claim support rate and contradiction rate on generated summaries

4. Error analysis
- inspect examples with high BERTScore but low claim support rate

This is the minimum experiment package that directly addresses the original research question.

## Recommended Workflow

### 1. Ingest MIMIC-III

```bash
python3 scripts/ingest_mimiciii_notes.py \
  --input-file data/mimiciii/NOTEEVENTS.csv \
  --output-dir data/mimiciii/raw
```

### 2. Prepare the default processed dataset

```bash
python3 scripts/prepare_datasets.py \
  --input-dir data/mimiciii/raw \
  --output-dir data/mimiciii/processed \
  --verifier-max-claims-per-example 6
```

### 3. Train the summarizer

```bash
python3 scripts/train_summarizer.py \
  --data-dir data/mimiciii/processed/summarization \
  --config configs/summarizer/gemma3_12b_qlora.json \
  --model-name google/gemma-3-12b-it \
  --output-dir artifacts/summarizer/gemma3_12b_qlora \
  --save-strategy steps \
  --save-steps 200 \
  --save-total-limit 2 \
  --eval-strategy epoch \
  --logging-steps 20 \
  --auto-resume
```

### 4. Train the verifier

```bash
python3 scripts/train_verifier.py \
  --config configs/verifier/deberta_v3_large.json \
  --data-dir data/mimiciii/processed/verifier \
  --output-dir artifacts/verifier/deberta_v3_large
```

### 5. Evaluate the full pipeline

```bash
python3 scripts/evaluate_pipeline.py \
  --raw-test-file data/mimiciii/raw/test.jsonl \
  --verifier-test-file data/mimiciii/processed/verifier/test.jsonl \
  --summarizer-dir artifacts/summarizer/gemma3_12b_qlora \
  --verifier-dir artifacts/verifier/deberta_v3_large \
  --output-file artifacts/evaluation/pipeline/evaluation_report.json
```

### 6. Inspect the comparison you care about

The generated report includes:
- aggregate `rouge` and `bertscore`
- `factscore` / average claim support rate
- contradiction and neutral-or-unsupported rates
- verifier held-out metrics
- correlation between overlap metrics and claim support
- representative high-overlap / low-support examples

## Human Annotation Workflow

The publishable version of the project should include a manually reviewed claim-faithfulness subset.

### 1. Export a claim annotation sheet

If you already ran full pipeline evaluation:

```bash
python3 scripts/export_claim_annotations.py \
  --pipeline-report artifacts/evaluation/pipeline/evaluation_report.json \
  --output-csv artifacts/annotations/claim_annotations.csv \
  --output-json artifacts/annotations/claim_annotation_export.json \
  --limit 25
```

If you want to generate the annotation set directly from models:

```bash
python3 scripts/export_claim_annotations.py \
  --input-file data/mimiciii/raw/test.jsonl \
  --summarizer-dir artifacts/summarizer/gemma3_12b_qlora \
  --verifier-dir artifacts/verifier/deberta_v3_large \
  --output-csv artifacts/annotations/claim_annotations.csv \
  --limit 25
```

### 2. Fill in the CSV

Annotate `human_label` using one of:
- `supported`
- `contradiction`
- `neutral`

Optional adjudication notes can go into `human_notes`.

### 3. Evaluate the annotated set

```bash
python3 scripts/evaluate_human_annotations.py \
  --annotation-csv artifacts/annotations/claim_annotations.csv \
  --output-file artifacts/evaluation/human_annotations/human_annotation_report.json
```

This report is the one that matters for the paper because it lets you compare:
- verifier agreement with human claim judgments
- ROUGE / BERTScore correlation with human claim support
- examples where overlap looks strong but humans still find unsupported claims

## Ablation And Analysis Suggestions

Recommended ablations:
- full dataset vs `narrative-only` filtered dataset
- default decoding vs beam-search decoding
- optional target-shortening debug setup for quick sanity checks

Recommended quantitative analysis:
- compare ROUGE-1, ROUGE-2, ROUGE-L, ROUGE-Lsum, and BERTScore F1
- report absolute gains over the baseline
- keep the evaluation split fixed across all experiments

Recommended qualitative analysis:
- inspect 20 to 50 predictions
- tag failure modes such as:
  - `admission_copying`
  - `generic_boilerplate`
  - `hallucinated_detail`
  - `missed_hospital_course`
  - `too_short`
  - `truncated`
- include a few success and failure examples in the report

Recommended interpretation:
- use the project to answer whether cleaner target supervision improves summary quality
- avoid claiming direct state-of-the-art comparison unless the setup is made strictly comparable to prior work

## Limitations

- verifier training currently relies on weakly supervised claim labels generated during preprocessing
- overlap metrics do not directly measure factual faithfulness
- the summarizer still struggles with heterogeneous hospital-course target styles
- some decoding settings can make outputs more generic or hallucination-prone
- model downloads require internet access on first use
- the recommended Gemma QLoRA path assumes CUDA
